Scripts break when a site changes.Agents pay for the same thinking every run.FluxIQ keeps what works and only thinks again when it has to.

Pay for what’s new

Routine runs replay saved steps with no model at all. AI is only called for something FluxIQ hasn’t seen before.

Your limits, per Flow

Cap how often AI can step in, how many tokens it uses, and what it spends. When a cap is hit, FluxIQ asks you or stops. Your call.

Checks that relax as trust grows

Results are checked on the first runs, then less and less often. Change the Flow and checking starts over.

You choose how much it fixes itself

Fully adaptive, approve every change, or no AI at all. Every repair is logged and can be reverted.

Two parts. One system.

The framework does the thinking and remembering. The extension does the clicking. They pair over a local connection you approve.

Framework · fluxiq 0.7

The engine

A TypeScript framework and control panel you run on your own machine. It builds Flows, runs them, checks the results, and repairs what breaks.

  • Automation Studio, a visual editor for Flows
  • Write Flows by hand in TypeScript, if you prefer
  • Datasets you can browse and export as CSV or JSON
  • Two-factor sign-in, roles, and encrypted API keys

How a Flow is born, and stays alive

  1. 01 · show

    Say it or show it

    Type what you want done, or record it once in your browser.

  2. 02 · build

    Built from real parts

    AI assembles the Flow only from actions FluxIQ actually has. Buying, deleting, or sending always waits for a person.

  3. 03 · run

    Replays without AI

    Saved steps run the same way every time, and results get checked until the Flow has earned trust.

  4. 04 · repair

    Fixes itself, with your say

    When a site changes or a check fails, FluxIQ works out why, proposes a fix, and keeps it only once a full run succeeds.

Where it’s going

From automations to whole applications.

FluxIQ’s own tools already run as programs on one framework. Automation Studio, the database manager, and background tasks each have their own screens and APIs.

The goal is for you to describe an outcome and have FluxIQ build the program around it: the interface, the data, the Flows that do the work, and the controls that keep it honest.

  1. nowMake the browser loop solid
  2. nextDeploy self-repairing Flows to the cloud
  3. thenIntegrations and Flows that build on Flows
  4. laterGenerate complete applications
